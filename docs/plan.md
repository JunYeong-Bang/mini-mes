# 전체 기능 계획 — 미구현 설계 포함

이 문서는 전체 목표입니다. 현재 구현된 테이블과 ERD는 [database.md](database.md)에 따로 기록합니다. 아래 후속 엔티티와 관계는 아직 코드나 DB에 존재하지 않습니다.

## 작은 단위로 진행할 순서

| 단계 | 기능 | 완료 기준 | 상태 |
| --- | --- | --- | --- |
| 1 | 환경, 프로젝트, DB 이력, 품목 관리 | 등록·목록·수정·검증, dev 예시, 실행 검증 | 이번 구현 |
| 2 | 설비, 품목별 공정 순서 | 설비 코드 중복, 선반·밀링·검사 유형, 공정 순서 중복 방지 | 예정 |
| 3 | 작업지시와 공정 복사 | 목표·납기·상태, 공정 스냅샷, 원본 변경 영향 차단 | 예정 |
| 4 | 분할 생산실적·불량 사유 | 수량·시간·설비·공정 순서 검증, 트랜잭션, 중복 제출·동시 입력 | 예정 |
| 5 | 현황·지표 | 현재 공정, 일별·공정별 처리량·불량률, 최종 양품·목표 부족 | 예정 |
| 6 | 로그인·권한·실적 수정 이력 | 관리자/작업자, 변경 사유·변경 전후 기록, 후속 공정 수량 검증 | 예정 |
| 7 | CSV 및 포트폴리오 정리 | 선택 기능, 시나리오·화면·설계 설명 | 여유 시 |

## 가상 공장 모델

작업지시 하나 = 생산 묶음 하나. 품목별로 순서가 정해진 공정을 진행합니다. 예: 구동축은 선반 → 밀링 → 검사. 작업지시 생성 시 당시의 공정명·순서·허용 설비 유형을 지시 공정에 복사합니다. 품목의 공정 마스터를 수정해도 이미 생성된 지시의 공정은 바뀌지 않습니다. 품목명 등 표시 정보의 스냅샷 범위는 3단계에서 별도로 결정합니다.

공정 간 동시 진행, 재작업, 묶음 분할·합치기, 실제 설비 연동은 제외합니다. 공정 하나 안에서는 여러 번 나누어 실적을 입력할 수 있습니다. 이전 공정이 완료되어야 다음 공정을 시작합니다.

## 수량과 완료의 정의 — 구현 전 합의할 업무 규칙

- 수량은 0 이상의 정수. 작업지시 목표 수량은 양의 정수
- 실적의 처리 수량 = 양품 수량 + 불량 수량. 실제 실적의 처리 수량은 1 이상으로 두어 빈 실적을 방지할 예정
- 첫 공정의 누적 처리량 ≤ 목표 수량
- 다음 공정의 누적 처리량 ≤ 이전 공정의 누적 양품 수량
- 첫 공정의 입력 가능량은 목표 수량, 다음 공정은 완료된 이전 공정의 누적 양품 수량
- 해당 공정의 누적 처리량이 입력 가능량과 같으면 공정 완료
- 이전 공정이 완료되기 전 다음 공정 실적은 입력 불가
- 이전 공정 양품이 0이면 다음 공정의 입력 가능량도 0. 실적을 억지로 만들지 않고 0개 공정 종료를 처리할 예정
- 마지막 공정까지 처리가 끝나면 작업지시 완료. **완료는 목표 양품 수량 달성을 의미하지 않음**
- 종료 시간 ≥ 시작 시간. 저장된 양품·불량 수량과 별도 불량 사유 수량 합도 일치해야 함
- 실적 저장, 공정 상태, 지시 상태 변경은 하나의 트랜잭션
- 후속 공정이 진행된 실적을 수정할 때 모든 후속 공정의 투입 상한과 완료 상태를 다시 검사
- 사용 이력이 있는 품목·설비는 삭제 대신 비활성화. 비활성 품목·설비의 신규 지시/실적 사용은 후속 단계에서 차단

## 작업지시 상태 전환 — 예정

| 상태 | 전환 조건 |
| --- | --- |
| 대기 | 지시 생성 직후, 실적 없음 |
| 진행 | 첫 유효 실적 저장 시 대기에서 전환 |
| 완료 | 모든 공정의 입력 가능량 처리 완료. 자동 전환 |
| 취소 | 초기에는 실적 없는 대기 지시만 관리자가 취소 가능 |

완료·취소 상태에는 신규 실적을 입력할 수 없습니다. 실적 수정으로 완료 조건이 변하는 경우의 재계산과 변경 이력은 6단계에서 구현합니다. 진행 중 취소는 이번 모델에 포함하지 않고 필요 시 별도로 설계합니다.

## 중복 제출·동시 입력 — 4단계에서 구현

동일한 폼을 두 번 제출해도 같은 실적이 두 번 저장되지 않도록 제출 식별자와 DB 고유 제약을 사용합니다. 동시 실적은 작업지시 또는 지시 공정을 잠그고, 누적 수량을 다시 계산한 후 저장합니다. 읽고 비교한 다음 잠금 없이 저장하는 방식은 수량 상한을 보장하지 못합니다. 이 기능은 현재 품목의 버전 검사와 별개이며 아직 구현하지 않았습니다.

## 지표의 계산 기준 — 5단계에서 구현

- 일별·공정별 처리량: 해당 실적 종료일(Asia/Seoul)과 공정 기준으로 처리 수량 합계
- 불량률: 같은 집계 대상의 불량 수량 합 ÷ 처리 수량 합 × 100. 처리량 0이면 ‘—’로 표시. 화면은 소수 둘째 자리 반올림
- 완성 수량: 해당 작업지시 **최종 공정 양품 합계**
- 목표 부족량: max(목표 수량 − 최종 공정 양품 합계, 0)
- 모든 공정 처리량 합은 작업량이며 완제품 수량으로 표시하지 않음
- 불량 사유 예시: 치수 불량, 표면 불량, 기타. 기타 사유는 설명을 요구할 예정

100개 지시 예: 선반 처리 100 = 양품 95 + 불량 5 → 밀링 처리 95 = 양품 92 + 불량 3 → 검사 처리 92 = 양품 90 + 불량 2. 지시는 완료, 완성 수량 90, 부족량 10. 공정 처리량 합 287은 완성 수량이 아닙니다.
